From Wallet Seed to Ethereum Address

Executive Summary

This project implements a web-based simulator of the Ethereum wallet pipeline, demonstrating the full cryptographic chain from a mnemonic phrase to a checksummed Ethereum address. The pipeline combines key generation, key derivation, public-key cryptography, hashing, and checksum encoding, each step handled by a distinct cryptographic primitive.

Historical Context

The technologies used in modern Ethereum wallets were developed over several decades:

  • 1977 - RSA: first practical public-key cryptography system
  • 2001 - SHA-2 / SHA-512: standardized by NIST
  • 2012 - BIP-32: hierarchical deterministic wallets
  • 2013 - BIP-39: mnemonic code for deterministic wallets
  • 2014 - BIP-44: multi-account HD wallets
  • 2015 - SHA-3: standardized by NIST, based on Keccak
  • 2016 - EIP-55: mixed-case checksum for Ethereum addresses

Note: Ethereum uses Keccak-256, which is the original submission to the SHA-3 competition. The standardized SHA3-256 differs from Keccak-256 in its padding convention - they are not interchangeable.

Cryptographic Pipeline

The Ethereum wallet pipeline combines five distinct cryptographic techniques, each serving a different purpose:

  • BIP-39 - Key generation: converts entropy into a human-readable mnemonic phrase, then derives a 512-bit seed via PBKDF2-HMAC-SHA512.
  • BIP-32 / BIP-44 - Key derivation: derives a hierarchical tree of private keys from the master seed, following the standard Ethereum path \(m/44'/60'/0'/0/0\).
  • secp256k1 - Public-key cryptography: derives the public key from the private key via elliptic-curve scalar multiplication \(Q = kG\). This is the same one-way function explored in HW01.
  • Keccak-256 - Hashing: hashes the public key to produce a 32-byte digest, of which the last 20 bytes form the Ethereum address.
  • EIP-55 - Checksum encoding: encodes the address in mixed-case hexadecimal to enable error detection without changing the address itself.

Key Distinctions

  • Key generation vs key derivation: BIP-39 generates the master seed from entropy (generation); BIP-32/BIP-44 derive child keys from that seed deterministically (derivation).
  • Public-key cryptography: secp256k1 provides the mathematical trapdoor, easy to compute \(Q = kG\), hard to reverse (ECDLP).
  • Hashing: Keccak-256 compresses the 64-byte public key into a 32-byte digest. One-way, fixed-size output, collision resistant.
  • Checksums: EIP-55 encodes redundancy into the address representation to detect typos, it does not add security.
  • Encoding: hexadecimal representation of binary data, no cryptographic properties, purely a display convention.

Discussion

The Ethereum wallet pipeline uses several different cryptographic techniques because each step has fundamentally different requirements:

  • BIP-39/BIP-32/BIP-44 need determinism and human-readability, the same mnemonic must always produce the same keys, and the phrase must be memorizable by humans.
  • secp256k1 needs a mathematical trapdoor, the relationship between private and public key must be easy to compute forward and hard to reverse.
  • Keccak-256 needs fixed-size output and collision resistance, Ethereum addresses are always 20 bytes regardless of public key content.
  • EIP-55 needs error detection without changing the address, a checksum that works at the encoding level, not the cryptographic level.

No single algorithm can satisfy all these requirements simultaneously, this is why the pipeline is a composition of specialized primitives rather than one monolithic function.

Conclusion

The Ethereum wallet pipeline is a carefully layered composition of cryptographic primitives, each chosen for its specific properties. The determinism of BIP-39 enables wallet recovery from a single phrase; the hierarchy of BIP-32/BIP-44 enables multiple accounts from a single seed; secp256k1 provides the public-key relationship; Keccak-256 compresses the public key into a manageable address; and EIP-55 adds a lightweight error-detection layer. Together they form a system that is both secure and usable.
